AgentJev 与 NanoJev 的核心差距深度剖析

      基于 2026 最新代码与权重实测
    


    

      

        

          1. 训练场景分布与任务目标
          业务 vs 游戏
        

        

          NanoJev 专攻高频街机游戏与具身路径规划（训练了 1.6 万条 ViZDoom 轨迹、50x50 迷宫与贪吃蛇）。


          AgentJev 专攻软件工程与企业级复杂语义决策（4,800 道代码审查、运维突发故障、发票核销与客服工单）。
        

        

          
NanoJev 优势: 连续空间反射

          
AgentJev 优势: 复杂语义对齐

        

      


      

        

          2. 上下文窗口容量与长状态容纳
          AgentJev 领先
        

        

          AgentJev 具备 2048 Tokens 的输入容量，能够完整吞下完整的 Git Diff、错误堆栈、JSON 数据库记录而零截断。


          NanoJev 限制在 1024 Tokens（候选超 256 即强制截断），在长技术文本或多轮对话中会丢失先验信息。
        

        

          
NanoJev: 1024 Tokens

          
AgentJev: 2048 Tokens (2x)

        

      


      

        

          3. 连续长链决策累积误差 (Compounding Error)
          存在差距
        

        

          NanoJev 在 256 步的迷宫与贪吃蛇中积累了专家回放轨迹（RL / 模仿学习强化），能在长时间多步中避免进入局部死循环。


          AgentJev 单步判断准确率极高（单步选择东面概率 56%+），但未经过长轨迹多步强化学习训练，在 100 步以上的长链游戏中仍需要外部 Harness（规划栈）辅助记忆。
        

        

          
NanoJev: 225步出迷宫

          
AgentJev: 需外挂记忆栈

        

      


      

        

          4. 推理架构与前缀 KV 复用 (Shared Prefix)
          AgentJev 领先
        

        

          AgentJev 实现了原生共享前缀计算（Shared Prefix Compute）。当面临 64 个甚至 255 个候选项时，环境状态只需在 Qwen3 骨干网络中计算 1 次，推理时间从 610ms 降至 299ms。


          NanoJev 采用简单的微批次并行，多候选状态仍存在重复编码开销。
        

        

          
NanoJev: 单候选重复前向

          
AgentJev: KV复用 (快 2x)
